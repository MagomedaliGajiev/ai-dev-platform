# Domain docs

## Before exploring

- Read `DOMAIN.md` at the repository root for agreed domain terms.
- Read ADRs in `docs/adr/` relevant to the area you are working on.
- If these files do not exist, proceed silently. Use the `domain-modeling` skill to create them when terms or decisions are agreed.

## Layout

Single-context: one root `DOMAIN.md` and repository-wide decisions in `docs/adr/`.

## Use agreed terms and decisions

Use the glossary's vocabulary in discussion, issue titles, proposals, and test names. If a needed term is missing, note it for `domain-modeling`.

If a proposal conflicts with an ADR, identify the ADR and explain why the decision should be reconsidered.
